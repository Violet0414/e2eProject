## 语法约定（解析契约）

### 元信息头（# 标题 + 列表项）

| 项 | 必填 | 说明 |
|---|---|---|
| 流程ID | 是 | 脚本 CASE_ID，格式 `DF-XXX`（XXX 为三位序号） |
| BASE_URL | 是 | 脚本配置区 BASE_URL |
| 优先级 | 否 | 仅记录用，不影响执行 |

### 步骤两型（有序号 `N.` 的行）

**动作步骤**（3 种）：

| 语法 | 说明 |
|---|---|
| `N. 打开页面 {route_path}` | 导航到 BASE_URL + route_path |
| `N. 填写数据` + 缩进二列表格<br>`N. 填写数据 { 字段: 值, ... }` | 填写表单。表格形式（字段名与值两列）或行内字典形式。**填写值自动捕获进上下文 CTX** |
| `N. 点击按钮 {按钮文本}` | 点击指定文本按钮 |

**校验步骤**（带 `校验：` 前缀，3 种）：

| 语法 | 说明 |
|---|---|
| `N. 校验：状态变更为 {期望状态}` | 断言页面出现期望状态文案（列表/详情/标签） |
| `N. 校验：提示为 {toast文本}` | 断言出现指定 toast 提示 |
| `N. 校验：与第M步填写数据一致：字段1、字段2` | 一致性断言：逐字段取页面实际值与第M步（须为"填写数据"步骤）捕获的 CTX 值比对，**收集全部差异后一次性报错**，输出字段级明细（`字段=期望值 vs 实际值`） |

### 上下文与变量

- 每个执行"填写数据"步骤后，`字段->值` 写入全局上下文 CTX
- 后续步骤的值支持 `${字段名}` 占位符，引用此前已捕获的值（如 `${单号}`）
- `${字段名}` 引用的字段必须在此前某步"填写数据"中出现过，否则解析期报错

### 其他

- `[via:api]` 仅为语法占位：标注在校验步骤末尾时，本期降级为 UI 校验，脚本内留 TODO 注释并在汇报中声明
- 校验步骤中的"字段"须与填写数据步骤中的字段名**原文一致**，才参与一致性比对
