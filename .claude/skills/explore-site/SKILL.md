# 页面探索

使用Playwright MCP对用户指定的页面URL进行功能模块完整探索，生成结构化探索记录和录制操作代码文件，供后续 generate-testcases-from-explore 技能生成测试用例。

## 【重要】核心要求

### 1. 必须输出两个文件
- **探索记录文件**：`explore_record.md` - 结构化记录所有元素信息
- **录制操作代码文件**：`recorded_code.py` - 所有元素操作的Playwright Python代码

### 2. 必须逐个操作所有类型的元素
对页面上的每个元素、每个表单中的元素都必须逐个操作，包括但不限于：
- **输入框**：文本输入框、数字输入框、密码框、文本域等
- **下拉框**：单选下拉、多选下拉、级联下拉（省市区等）
- **选择框**：单选框、多选框、开关组件等
- **日期/时间控件**：日期选择器、时间选择器、日期时间选择器
- **按钮**：查询按钮、重置按钮、新增按钮、编辑按钮、删除按钮、确定按钮、取消按钮、关闭按钮等
- **其他控件**：附件上传、Tab标签页、翻页控件、表格操作等

每一个元素操作都必须生成对应的Playwright Python代码并保存到 `recorded_code.py` 文件中。

**本技能聚焦于用户指定的单个页面。操作后跳转的页面（如新增/编辑/详情表单页）通过子会话探索，防止主会话上下文溢出。**

## 文件路径规范

**所有运行时生成的文件统一放在 `~/{项目目录}/explore_output/{当前日期}_{时间}/` 下（需初始化时提前创建），严禁在skills目录下创建任何文件或目录。**

**【必须输出两个核心文件】**：
- **探索记录文件**：`~/{项目目录}/explore_output/{当前日期}_{时间}/explore_record.md` - 记录所有元素信息、接口等
- **录制操作代码文件**：`~/{项目目录}/explore_output/{当前日期}_{时间}/recorded_code.py` - 保存所有元素操作的Playwright Python代码

- 截图目录（需初始化时提前创建）：`~/{项目目录}/explore_output/{当前日期}_{时间}/screenshots/`
- 参考文档：`~/{项目目录}/files/templates/test_points_requirement.md`

## 输入

- **页面URL**：用户提供的待探索页面URL
- **登录凭据**（可选）：如页面需要登录，用户提供账号密码
- **参考文档**：`~/{项目目录}/files/templates/test_points_requirement.md`

## 探索流程

### 1. 初始化

- 初始化时，创建 `~/{项目目录}/explore_output/{当前日期}_{时间}/` 和 `~/{项目目录}/explore_output/{当前日期}_{时间}/screenshots/` 目录
- **创建两个核心文件**：
  - `explore_record.md` - 初始化探索记录结构
  - `recorded_code.py` - 初始化录制代码文件，添加导入语句和基础设置
- 使用Playwright MCP打开浏览器，导航到目标页面URL
- 如页面需要登录，先执行登录操作再导航到目标页面
- 记录页面标题和当前URL

### 2. 主页面探索

聚焦当前页面，按以下类别进行探索。遇到跳转页面时，开启子会话探索（见第3步）。

#### 一、列表查询

**【必须逐个操作所有类型的元素】**

- 记录查询条件字段及其类型（文本/日期/时间/树形/省市区级联等）
- 记录查询条件的默认提示文字
- **逐个操作所有输入框**：输入测试数据、清空、验证输入效果
- **逐个操作所有下拉框**：展开下拉、选择不同选项、记录选项值、选择器
- **逐个操作所有日期/时间控件**：选择日期、修改日期、清空日期
- **逐个操作所有单选框/多选框**：点击选择、取消选择
- **逐个操作所有按钮**：点击查询、点击重置、点击展开/收起
- 测试选择类查询条件的下拉选项
- 测试日期/时间类查询条件的控件
- 测试树形结构的展开收起、层级选项
- 测试省市区级联的过滤逻辑
- 测试单个查询条件查询、多条件组合查询、查询结果为空
- 测试翻页后查询、重置查询条件、展开收起查询条件
- 记录按钮名称
- **【重要】每个元素操作都必须生成对应的Playwright代码并保存到 `recorded_code.py`**

#### 二、列表数据

- 记录表头字段
- 记录字段值（新增后对比新增值、编辑后对比编辑值、无操作对比接口响应）
- 查询后列表数据、删除后列表数据

#### 三、列表翻页

**【必须逐个操作所有翻页元素】**

- 记录翻页控件样式
- **逐个操作所有翻页元素**：页码点击、页码输入、上一页/下一页、首页/末页
- **逐个操作每页条数切换下拉框**：选择不同条数
- 测试页码点击、页码输入、上一页/下一页、首页/末页
- 测试每页条数切换、翻页后数据显示
- **【重要】每个翻页元素操作都必须生成对应的Playwright代码并保存到 `recorded_code.py`**

#### 四、列表操作

**【必须逐个操作所有按钮】**

- 记录操作按钮名称
- 记录操作按钮与数据状态的对应关系
- **逐个点击所有操作按钮**：新增、编辑、删除、详情等
- 测试删除操作（确认弹窗、删除后列表不显示）
- 测试批量删除（确认弹窗、未选择提示、查询后全选）
- 测试其他批量操作（未选择提示、选择后操作所选数据）
- **【重要】每个按钮操作都必须生成对应的Playwright代码并保存到 `recorded_code.py`**

#### 五、接口监测

- 记录探索过程中观察到的接口调用（URL、请求方法、请求参数、响应格式）

### 3. 跳转子会话探索

当主页面操作导致页面跳转时，必须使用Agent工具开启子会话进行探索，防止主会话上下文溢出。

**触发条件**：
- 点击新增按钮 → 新增表单页
- 点击编辑按钮 → 编辑表单页
- 点击详情按钮 → 详情表单页
- 其他导致页面跳转的操作

**子会话执行方式**：
使用Agent工具spawn子Agent，子Agent接收跳转页面的上下文信息，独立完成探索后将结构化结果返回给主会话。

**子会话输入**：
- 跳转触发操作（如"点击新增按钮"）
- 跳转后页面URL
- 页面类型（新增表单/编辑表单/详情表单/其他）
- 参考文档路径：`~/{项目目录}/files/templates/test_points_requirement.md`

**子会话探索内容**：

**新增表单页**：
**【必须逐个操作所有类型的元素，每个元素操作都生成代码】**
- 页面标题（必须记录弹窗标题的精确文本）
- 弹窗确定按钮文本（必须记录按钮实际文本）
- 弹窗确定按钮选择器（必须使用Playwright获取精确选择器）
- 所有字段及其类型、默认提示、必填标识
- **逐个操作所有表单元素**：
  - **输入框**：逐字段输入测试数据、记录选择器、清空重新输入
  - **下拉框**：逐个展开、选择不同选项、记录选择器和选项值
  - **单选按钮**：逐个点击选择、记录选择器
  - **多选框**：逐个勾选/取消勾选、记录选择器
  - **日期/时间控件**：逐个选择日期/时间、记录选择器
  - **文本域**：输入多行文本、记录选择器
  - **附件上传**：选择文件上传、记录选择器
  - **其他控件**：逐个操作并记录
- **【重要】级联下拉选项处理**：如果是级联下拉选项（如省市区三级联动、区县-街道-社区-网格四级联动），**必须按顺序逐个选择并等待加载**：
  1. 先展开第一级下拉，记录选择器，获取并选择第一级选项
  2. 等待第二级选项加载出来后，记录第二级选择器，选择第二级选项
  3. 等待第三级选项加载出来后，记录第三级选择器，选择第三级选项
  4. 如有第四级，继续等待加载并选择
  5. **必须完整选中所有级联项，不能只选一级就停止**，否则会遗漏尾部级联选项的测试
- 必填项验证（不填提示、填写保存）
- 非必填项验证（不填保存、填写保存）
- **逐个操作所有按钮**：关闭、保存提交、取消
- 保存后列表显示该数据、字段值正确
- **【重要】每个表单元素和按钮的操作都必须生成对应的Playwright代码并保存到 `recorded_code.py`**

**编辑表单页**：
**【必须逐个操作所有类型的元素，每个元素操作都生成代码】**
- 页面标题（必须记录弹窗标题的精确文本）
- 弹窗确定按钮文本（必须记录按钮实际文本）
- 弹窗确定按钮选择器（必须使用Playwright获取精确CSS选择器）
- 字段回填验证（与新增值对比）
- **逐个操作所有表单元素**：
  - **输入框**：逐字段修改数据、记录选择器、清空
  - **下拉框**：逐个展开、选择不同选项、记录选择器和选项值
  - **单选按钮**：逐个点击选择、记录选择器
  - **多选框**：逐个勾选/取消勾选、记录选择器
  - **日期/时间控件**：逐个修改日期/时间、记录选择器
  - **文本域**：修改多行文本、记录选择器
  - **附件上传**：重新上传文件、记录选择器
  - **其他控件**：逐个操作并记录
- **【重要】级联下拉选项处理**：如果是级联下拉选项（如省市区三级联动、区县-街道-社区-网格四级联动），**必须按顺序逐个选择并等待加载**：
  1. 先展开第一级下拉，记录选择器，获取并选择第一级选项
  2. 等待第二级选项加载出来后，记录第二级选择器，选择第二级选项
  3. 等待第三级选项加载出来后，记录第三级选择器，选择第三级选项
  4. 如有第四级，继续等待加载并选择
  5. **必须完整选中所有级联项，不能只选一级就停止**，否则会遗漏尾部级联选项的测试
- 清空非必填保存
- **逐个操作所有按钮**：关闭、保存提交、取消
- 关闭不更新、保存后更新、取消不更新
- 附件回显
- **【重要】每个表单元素和按钮的操作都必须生成对应的Playwright代码并保存到 `recorded_code.py`**

**详情表单页**：
**【必须逐个操作所有元素，每个操作都生成代码】**
- 字段名称和值（与新增/编辑一致）
- 图片预览、附件下载
- **逐个操作所有TAB**：点击切换、记录选择器
- **逐个操作所有按钮**：返回、关闭
- 空字段值显示、长字段值显示效果
- **【重要】每个TAB和按钮的操作都必须生成对应的Playwright代码并保存到 `recorded_code.py`**

**子会话返回结果**：
子Agent完成后，将探索结果以结构化文本返回，主会话将结果整合到探索记录的对应章节中。

### 4. 记录规范

只记录 generate-testcases-from-explore 技能生成测试用例所需的必要信息：
- **【必须】元素的字段名、类型、默认提示（使用Playwright获取占位符文本）、选项值**
- **【必须】元素定位选择器（使用Playwright的 `page.locator()` 或开发者工具获取精确CSS选择器/XPath）**
  - **【重要】如果探索过程中对某个元素进行多次定位尝试，必须记录最终成功操作的那个正确定位器，覆盖之前的失败尝试**
  - **【重要】在 recorded_code.py 中只保留使用最终正确定位器的操作代码，删除失败尝试的代码**
- 校验规则和测试结果
- 操作触发条件和结果
- 接口调用信息

#### 4.1 元素选择器通用优先级规则
1. 表单标签约束+属性定位（placeholder/name/id/data-*）＞纯属性定位＞文本定位＞父级类约束选择器＞索引选择器（仅兜底使用，禁止优先使用）
2. ElementUI组件优先基于组件类做范围约束，避免全局模糊匹配，选择器必须保证`page.locator(selector).count() = 1`唯一匹配
3. 弹窗、表格行内按钮必须增加父级范围约束，禁止使用无约束全局文本选择器
4. 禁止使用页面动态随机ID、临时动态class作为定位器
5. 针对页面初始化自带默认值、DOM 初始状态未展示placeholder，清空内容后才显示占位符的输入框： 必须先通过 Playwright 操作清空输入框内容，再调用page.locator().getAttribute('placeholder')获取真实占位符文本，禁止直接判定为无占位符； 获取到占位符后，依旧优先使用表单标签约束 + input[placeholder="xxx"]作为首选定位器；
「默认提示」列统一格式填写：页面初始默认值：{默认值}，清空后占位符：{占位符文本}。

#### 4.2 各类型控件标准CSS选择器规范（必须严格遵循）
##### 1. 单行文本输入框 el-input
|控件用途|标准CSS选择器|说明|
| ---- | ---- | ---- |
|带唯一占位符（首选）|`input[placeholder="请输入用户名"]`|稳定性最高|
|表单标签约束+占位符|` .el-dialog:has-text('新增') input[placeholder='请输入场馆名称']`|防止多表单相同占位符冲突|
|name属性定位|`input[name="username"]`|后端绑定字段场景优先|
|兜底索引定位|`.el-form-item:nth-child(1) .el-input__inner`|仅前几种无法唯一定位时使用|

##### 2. 多行文本框 textarea
|控件用途|标准CSS选择器|说明|
| ---- | ---- | ---- |
|占位符定位|`textarea[placeholder="请输入备注信息"]`|常规首选|
|表单约束定位|`".el-dialog:has-text('新增') textarea[placeholder='请输入场馆类型']"`|多表单场景必用|

##### 3. 下拉选择框 el-select
|控件用途|标准CSS选择器|说明|
| ---- | ---- | ---- |
|下拉回显输入框|`".el-dialog:has-text('新增') .el-select:has(input[placeholder='请选择区县'])"`|点击前输入回显框|
|下拉展开箭头按钮|`".el-dialog:has-text('新增') .el-select__caret`|用于打开下拉面板|
|下拉单个选项|`".el-dialog:has-text('新增') .el-select-dropdown__item:has-text('启用')`|精准选中指定选项|
|下拉面板容器|`".el-dialog:has-text('新增') .el-select-dropdown"`|下拉弹窗外层容器|

##### 4. 级联选择器 el-cascader（省市区/多级联动）
|控件用途|标准CSS选择器|说明|
| ---- | ---- | ---- |
|级联回显输入框|`".el-dialog:has-text('新增') .el-select:has(input[placeholder='请选择区县'])"`|输入回显区域|
|级联展开箭头|`".el-dialog:has-text('新增') .el-cascader__caret`|打开级联选择面板|
|一级级联选项|`".el-cascader-panel .el-cascader-node:has-text('贵州省')`|第一级选择节点|
|二级级联选项|`".el-cascader-panel .el-cascader-node:has-text('贵阳市')`|等待接口加载后选择|
|三级级联选项|`".el-cascader-panel .el-cascader-node:has-text('南明区')`|必须逐级选择，不可跳过层级|

##### 5. 单选框 el-radio
|控件用途|标准CSS选择器| 说明                                                                               |
| ---- | ---- |----------------------------------------------------------------------------------|
|单个单选按钮（推荐首选）|`.el-dialog:has-text("新增园区") .el-form-item:has-text("是否制定中长期发展规划") .el-radio:has-text("是")`| 1. 最外层限定弹窗 / 页面容器，隔离全局同名元素干扰；2. 通过el-form-item+表单标签精准锁定当前单选组，避免误命中其他表单项单选框；3. 直接定位可点击label.el-radio，符合 ElementUI 交互特性，点击稳定不失效                                                                       |
|单选组容器|`.el-dialog:has-text("新增园区") .el-form-item:has-text("性别") .el-radio-group`| 必须基于弹窗 + 所属表单项做上层约束，禁止全局直接定位el-radio-group；仅用于获取单选框全部选项、遍历选项、校验单选组选中状态，不用于直接点击操作 |

1. **强制上层容器约束**：所有表单控件选择器必须以页面 / 弹窗容器作为最外层前缀（示例：`.el-dialog:has-text("新增园区")`），禁止全局裸写选择器，杜绝多弹窗、多表单场景下元素误命中。
2. **组定位依托`el-form-item`**：表单左侧标签文案仅存在于`el-form-item`容器内，**禁止使用`el-radio-group`匹配表单标签文本**，否则会出现元素查找失败。
3. **交互操作仅允许点击`label.el-radio`**：所有单选点击业务逻辑，只能使用「单个单选按钮（推荐首选）」选择器；单选组容器、原生input选择器仅可用于属性查询、遍历、结果断言场景，严禁用于点击操作。
4. **统一使用`has-text()`模糊文本匹配**：规避页面换行、首尾空格、DOM格式化压缩导致的精准文本匹配失败问题。

#### 4.3 禁止使用的选择器类型
1. 无父级约束纯类选择器：`.el-input`、`.el-button`，会匹配页面内全部同类元素
2. 全局无约束文本按钮：`button:has-text("确定")`，多弹窗场景会定位冲突
3. 优先使用索引定位器：`.el-form-item:nth-child(3) input`，仅所有属性、文本定位失效时兜底使用
4. 动态随机ID、临时哈希类名：`#el-id-xxx`、`.css-hash-xxx`，页面刷新后定位失效

**获取方法**：
- 默认提示：使用 `browser_snapshot` 或 `page.locator().getAttribute('placeholder')` 获取
- 元素定位选择器：使用 `browser_snapshot` 提供的选择器，或通过 `page.locator('selector').count()` 验证唯一性
- 对于下拉选项：展开下拉后使用 `page.locator('selector').innerText()` 获取所有选项文本
